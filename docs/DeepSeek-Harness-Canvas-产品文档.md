## 一、产品概述

### 1.1 一句话定义

一个运行在 DeepSeek Harness 上的插件，把项目组织成一张无限画布，画布上的每张文件卡片绑定一个独立的 Agent 会话，引用关系在卡片之间传递数据，最终产出 PPT、网页、文档、图表等任意文件形态。

### 1.2 核心设计理念

**文件即产物，卡片即会话，引用即数据。**

- **文件即产物**：画布上的一切与磁盘一一对应，产物形态由文件证据认定，不需要预先声明“这是 PPT 模式”或“这是网页模式”。
- **卡片即会话**：每张卡片绑定一个独立 Agent 会话，会话只负责当前卡片的产物生成，上下文天然隔离，互不污染。
- **引用即数据**：卡片之间只有一种连线——**引用**。B 引用 A，表示 B 的产物建立在 A 的产物之上，这是唯一的显式数据通道：Agent 通过它拿上游产物作输入，而非自动感知全画布。

连线的语义被刻意收窄到只剩取样一个方向。改自、接着、对照、批注这些协作语义不再由连线表达，而是交给卡片命名、产物内引用与共享便利贴承载——**能靠约定表达的，就不该变成画布上的结构负担**。

### 1.3 与同类方案的区别

| 维度 | 传统 AI 创作工具 | 本插件 |
|------|----------------|--------|
| 上下文 | 单一长会话，上下文膨胀 | 每张卡片独立会话，按需注入 |
| 产物形态 | 预定义模式 | 文件证据自动认定，可扩展 |
| 协作方式 | 聊天框描述 | 引用关系显式传递数据 |
| Agent 可见范围 | 全部内容 | 仅当前卡片 + 显式引用 |
| 扩展方式 | 加功能分支 | 加形态注册表条目 |


## 二、核心概念

### 2.1 项目（Project）

一个项目对应一张无限画布，底层绑定一个工作区目录。项目是持久化、可分享、可复用的容器。**项目的身份写在目录自己身上**（目录里的板面文件记着它是哪张画布，F1.9），所以这个容器连同它的目录一起被改名、搬家、拷贝或交给别人，都还是同一张画布。

### 2.2 卡片（Card）

画布上的最小创作单元，与磁盘文件一一对应。卡片 id 是画布铸出的 6 位随机字母（座位身份），产物文件路径记在卡片的 `file` 字段上（v1.49 起，详见技术文档 §十一）。卡片绑定的产物可以是单文件（如 `deck.html`），也可以是含 `index.html` 的目录（如站点）。

### 2.3 会话（Session）

每张卡片绑定一个独立的 Agent 会话。会话的 system prompt 注入当前卡片的元信息（路径、形态、项目风格），工具调用只作用于当前卡片绑定的文件。

### 2.4 引用（Source）

卡片之间的唯一有向连线：**B 引用 A**，即 A 是 B 的上游产物来源。一张卡片可以有多个上游，也可以被多张卡片引用。

引用边的建立有两条途径：用户手动连线，以及**自动对账**——产物里真实引用到的素材，反向补上引用边。

引用数据独立于产物文件，作为画布元数据持久化：本机读写的真源是存储领域，同时它也是**随目录走的板面快照**里的一部分（F1.10），于是换成另一台机器打开同一个目录，引用关系跟着回来。

### 2.5 形态（Kind）

产物的类型，由文件证据自动认定。一种形态对应注册表中的一个条目，定义寻址、预览、导出、发布方式。

| F1.9 | 画布身份随目录走 | 一个画布目录**自己记着它是哪张画布**。于是把目录改名、搬到别处、或整个交给同事，重新绑定时认回的是**同一张画布**：座位、引用、便利贴原样在。判据是「记录里那个旧路径还在不在」——**旧路径没了＝目录被搬走了**（认回来）；**旧路径还在＝这是拷出来的一份**（给它一份自己的新身份，否则两个文件夹共用一个板面，在一边删掉卡片另一边也会消失）。没在这台机器上见过的目录（内含板面文件、存储域里没有记录）照它自己的身份收下，所以它从别的机器来也接得住；而第一次绑定一个老目录时**一个字节都不用迁**——没有板面文件就退回「路径摘要」这套老身份，已存在的画布因此原地不动（v1.47） |
| F1.10 | 板面随目录走 | 画布目录里多一份 `.dsh-canvas/board.json`：**这张画布是谁**（画布 id、名字、风格档案）加**板面本身**（卡片与它们的座位、引用边、便利贴）。座位还带一个**只在为真时写**的标记：**这一格生来就没有产物**——它是 F1.11 那条豁免（空座位不算失效）的载体，于是这份豁免也跟着目录走。标准 JSON、排序输出，可读、可 diff、可手改、模型也能直接读；改动板面后写回一次，**内容没变就不写**（不惊动文件监视器、不产生空 diff）。它是**投影不是真源**：本机的读写与命中测试仍走存储领域，写失败只记一行日志（目录只读或沙箱拦下时，板照常可拖可连），而**读不懂的文件绝不覆盖**（可能是手改到一半，也可能是更新格式写的）。跟着走与不跟着走的划线处是**属性归谁**：作品的关系与布局走，`sessionId`（换台机器就是另一个会话）、视图状态这类本机的东西不走。目录里的这份文件认不出卡片的**对话**、也不认视图状态，重建时按文件证据重新认定形态 |
| F1.11 | 清理失效卡片 | 产物已被删除（或改名）的卡片**留在板上**——它可能只是切了分支、也可能你只是想让这一格还在，所以插件从不自动清它，卡片以预览变淡示意（F3.5）。代价是清起来只有选中面板一条路，一张一张确认；板上攒下十几张就是删掉整张画布的动机。现在缩放条上有一枚 **清理失效卡片 (N)**：只在板上真有这种卡时出现（空板上一颗多余的按钮都没有），N 就是实时的张数，点了先问一句再动手。**「失效」在这里只指一件事：产物确实丢了**——探针能把这条路径解析出来、且明确回答没有这个文件，而这张卡也不是「建座时就没有产物」的空卡。所以三样东西**不算**、也不会被清：还没写过产物的空座位（刚落座等着写、位图等着生成、Agent 先落位后写文件，缺产物是**正常状态**而不是丢了文件）、探针答不上来的卡（路径不可解析、沙箱或权限拒绝——答不上来就不许下结论）、以及整个画布目录都读不到时（那时每张卡看起来都缺，而「真没了」与「探针坏了」从这里分辨不出，于是整体拒绝，想清空整张画布请走「移除画布」）。按钮上的 N 与真正会少掉的卡是**同一个集合**，所以清完会说一句实数：确有读不到而被留下的，照实说有几张。清掉的是**卡片**，不是文件：磁盘上的任何东西都不会被删，拿掉一张会连带忘掉它绑定的对话与引用关系——这正是要先问一句的理由（v1.47） |
| F1.12 | 卡片名 | 每张卡片有**自己的名字**，写在卡片最上沿那一条上（名条），**点一下就地变成输入框**：回车或点到别处提交，Esc 撤回。名字不只是标签——**改名字会连同磁盘上那一项一起改**：文件形态改文件名（`brief.md` → `市场分析.md`，扩展名留着）、目录形态改目录名（应用与站点的产物是「一个目录带 `index.html`」，所以改的是那个目录，入口页跟着搬：`myapp/index.html` → `市场分析/index.html`）；产物就是画布根目录本身的那种（根上的 `index.html`）拒改，理由直说，因为改它等于改画布目录，该走画布自己那条路。**撞名自动带序号**（`市场分析-2.md`），判据在磁盘上、与建卡脚手架同一个规矩——这时卡片上仍写着用户打的那个名字，路径自己带着序号，两者各说各的真话。没写名字的卡片**按产物推名字**：目录形态取目录名（应用卡因此显示「myapp」而不是「index.html」），其余取文件名去掉扩展名——老画布一张也不用迁，它们读出来正是原来显示的样子。名字跟着目录走（写进 `.dsh-canvas/board.json`，F1.10）：把文件夹交给同事，板面显示的还是你起的那批名字。改名**不动**卡片身份、会话绑定与引用关系（座位 id 与文件名早在 v1.49 就分了家），也**不动**产物里的内容——别的卡片里已经写下的旧路径（历史对话里的 `@旧名`、产物里写死的相对路径）不会跟着改，这是这类改名的固有代价（v1.53）。**新建的卡片从落座那刻就有名字**（v1.54）：名字按**类型 + 序号**自动铸（`文本1`、`应用1`、`设计1`，第二张起序号递进；删掉 `文本1` 再建，序号会让出来），并且铸出来的名字**直接当产物文件名用**——`文本1.md`、`应用1/`、`设计1.design`，名字与磁盘从出生就是同一句话，记录里一个 `name` 都不用多写。类型名的出处与卡面元数据是同一份（`kindLabel`），改类型名两处一起变。把**已有**产物摆上画布（项目文件、`canvas_create_on_board` 的 type=card）不做这一步——那份产物自己的文件名就是最好的名字 |
| F1.13 | 产物按类型分目录 | 一张画布曾经只有**一层**：所有产物都落在项目根上，`产品需求文档.md`、`图片.png`、`视频.mp4`、`音频.mp3`、`设计稿.design` 与几个应用目录挨在一起。只要产物超过十件，文件管理器里就只剩一串名字。现在**新建的卡片按类型落进子目录**：`docs/`（文本）、`apps/`（应用）、`designs/`（设计）、`images/`（图片）、`videos/`（视频）、`audio/`（音频）、`data/`（数据）、`files/`（文件）、`folders/`（文件夹）——打开项目目录就是一张分类表。**卡片名不变、身份不变、引用不变**：路径只是多了一层壳（`docs/文本1.md` 这张卡仍叫「文本1」），改名改的还是它自己那一项，也在它自己的目录里。**老画布第一次打开时自动整理**：只搬**平铺在项目根上**的条目，一次一条、撞名带 `-2`、失败就留在原地（原样可读，下次再试）；已经在类型目录里的一个都不动，所以整理可以反复跑、不会越搬越深。**四样刻意不搬**：根上的 `index.html`（整张画布就是它的产物，搬走等于拆了它）、同一个根条目下挂着不同形态的卡片（搬成 `apps/` 会拆掉文档，搬成 `docs/` 会拆掉应用）、没有对应目录的自定义形态（猜一个目录比留在根上更坏）、用户自己整理过的子目录（这是约定，不是管制——`decks/intro.html` 整块进 `apps/decks`）。**绑定一个已有的文件夹**时也认这层结构：`apps/应用1/index.html` 会被发现并摆上画布，不会因为多了一层而整目录消失。 |

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F2.1 | 形态注册机制 | 一种产物形态一个注册表条目，定义寻址、预览、导出、发布方式 |
| F2.2 | 文件证据认定 | 形态由文件扩展名和内容自动认定，不由用户声明 |
| F2.3 | 内置形态 | **应用（webapp）**、HTML Deck、站点、文本（Markdown）、设计、图片、视频、音频、数据图表 |
| F2.4 | 形态扩展 | 新增形态只需加注册表条目，不改散落分支 |
| F2.5 | 应用节点 | 新建「应用」即建一个**文件夹**并写入 web 应用脚手架（v1.25）：组件用原生 **Web Components**（无需构建、无框架运行时），UI 用 **shadcn 设计令牌**（CSS 自定义属性可穿透 shadow DOM，一套变量驱动全部组件）；全屏预览把本地资源**内联**进沙箱 iframe |
| F2.6 | 设计节点 | 「设计」卡片的产物是一份**场景图设计文档**（`.design`，v2 信封 + scene-graph 快照；与 SVG 无关，旧 v1 文件报错要求重新生成）。预览与编辑是**同一块画布的两个模式**：预览只有视口手势（拖拽平移 / 滚轮缩放）与左下 HUD，交付查看是干净画面；编辑多出左右两栏面板（页面 / 图层 / 属性），画布上可点选、拖移、改属性、undo，改稿停手后自动写回文件。模型侧读 `canvas_design_read`、改 `canvas_design_edit`（批量结构化 op：upsert / setProps / move / delete / reorder）——**一卡一份文档**，改稿不改文件文本。画板尺寸、图层纪律与编辑礼节由设计卡的**会话预设**给出（F3.16）。**容器的高度随内容，不按「屏」切（v1.55）**：预设给的是**宽度**菜单（手机 375 宽、平板 834 宽、桌面 / 官网 1440 宽）与固定规格稿件（海报 1242×1660、社交方图 1080×1080、幻灯片 1920×1080、横幅 1920×600）；网页与应用**一个容器装一整页**，多屏才看得完的内容在同一个容器里**连续**往下排，不拆成「首屏 / 第二屏 / 第三屏」的多个容器。要多容器只有两种情形：用户点名要多屏并排（多屏对比 / 流程走查），或交付物本身就是序列（幻灯片的每一页、海报系列）。**属性面板按类型给格子（v1.62）**：形状一节有通用项（尺寸、圆角统一或四角独立、容器裁切溢出）与**按类型才有的**几格——多边形的**边数**、星形的**角数 + 内径**、椭圆的**弧**（起点 / 扫过角 / 内径，一键在「弧」与「完整椭圆」之间来回）；文本一节把排版补齐——**内容、字体、字重、字号、行距（可自动）、字距、水平对齐、尺寸行为**（自动宽高 / 自动高度 / 固定 / 截断）；外观一节除填充与不透明度外多一格**图层混合模式**。两条与「值能不能画出来」有关的硬规矩：**字体下拉里只列真注册进 `fontManager` 的字面**（列一支没装上的，表现是文字画成空白且不报错），**换字体时字重一起落到新字面真有的那一档**；边数夹在 3–60、内径与弧内径夹在 0–1。**页面管理（v1.63）**：左栏最上面那一段管页面——**新增**（标题栏 ＋，默认名「页面 N」取第一个空位）、**复制**（新页带上源页整棵子树，插在源页右边并切过去）、**重命名**（行尾铅笔，双击行也可以）、**删除**（最后一页拒删）。复制是**我们自己接的**（上游 page actions 只有切页 / 新建 / 删除 / 移动 / 重命名 / 改页色）；**删除要二次确认**，因为上游的删除是不进撤销栈的死删（见下条）。多页之后画布、命中、贴合**一律只算当前页**：容器可以分页摆，复制出来的页与原件坐标相同，范围不圈就是「看到别页的东西」而界面上一切正常。**图层默认折叠（v1.67）**：左栏下面那一段照 Figma 来——**一进来所有带子节点的行都是折着的**，只看得见顶层那几个画板，点箭头才展开（用户原话：「分上下两栏，上面是 page，下面是图层，图层默认折叠不展开」）。一进来铺开几百行不是信息更多，是看不见结构：第一屏全被第一个画板的子节点占满，而此刻要知道的是「这份稿子里有几个东西」。两条配套规矩：**新出现的节点（新画板 / 新分组）默认也是折叠的**；**用户动过的不再自动改**——画布每落一次盘就换一份快照，若每次重算「可展开就折叠」，刚点开的容器会自己折上。画布上点选时，选中项藏在折叠的祖先里会**先让开那几层再滚过去**（这条 v1.63 就有，现在与「默认折叠」共同成立）。 |

| F2.7 | 媒体节点（图片 / 视频 / 音频） | dock 上三个入口，各坐一张**空座位**的卡（媒体产物没有「装得下它的文本种子」，所以 `present: false` 诚实显示「还没有东西」，直到一次生成跑完）。产物各认领一个 kind：`image`（png / jpg / webp / gif / svg / avif）、`video`（mp4 / mov / webm / m4v）、`audio`（mp3 / wav / m4a / aac / ogg / flac / opus / wma，v1.70 新增）。**生成走会话**，与文本 / 设计节点同构：用户说「生成…」，卡片会话按媒体预设调 `canvas_generate_image` / `canvas_generate_video` / `canvas_generate_audio`，产物落在**本卡自己的路径**上——「改这张」与「新建一张」只差 `cardId` 一个参数。**后端从 DSH 自己的模型配置读**（v1.70）：地址、密钥的环境变量名、模型名都在 `llm-pi-ai` 那条设置段的 `providers` 字典里，插件**按模型族自动挑**（含 `seedream` ⇒ 图片、含 `seedance` ⇒ 视频），用户加一条 doubao 路线即可用，插件不用改配置；两条服务（`settings` / `credentials`）走 `ctx.get` + 形状校验，**不进 `inject`**，缺了只让媒体生成落到诊断上而不是让插件加载失败。挑不到路线时给的是**能让人行动的那句话**：想要哪种能力、按什么名字找的、现有路线有哪几条。三条生成共用一条路径：能力拿到的是**路径不是座位 id**、生成完**重读一次产物形态**、失败是**一份答案不是异常**。音频的生成**走豆包语音**（`doubao-seed-audio-1-0`）：它的地址、密钥与计费都和方舟不是同一套（鉴权是 `X-Api-Key`，不是 Bearer），所以一条为方舟写的路线**不能直接服务音频**——插件会把音频请求改投语音那条主机，并且在一把 key 两边不通用时说清「这是另一把 key、去哪儿改」。预览：图片与视频用原生控件，音频是播放条 + 文件名。**卡面画的就是产物自己（v1.72）**：图片卡是那张图、视频卡与音频卡各是它们的原生播放器——**能在这里播，也能拖进度条**（控件自己吃掉指针，所以拖它不会把卡片拽走；图片没有控件，于是点它＝选中、拖它＝拖卡，与别的卡片手感一致；双击一律进全屏，卡片上不抢这个手势）。卡面与全屏预览**读的是同一条产物、用同一批文案**：产物还没生成、文件过大（16MB 上限）各有一句人话，「产物在里面是空的」退回大纲行占位。**引用进来的图片会自动当参考图（v1.74）**：画布上从一张图片连到图片卡 / 视频卡，那条边在生成时就变成 `image`（图生图）或首帧 `image_url`（图生视频）——不用先发布成链接，也不用在提示词里额外说明；要换一张用 `referenceCardId`，视频还能用 `referenceRole` 指定首帧 / 尾帧 / 参考图。**这张卡用哪个模型生成，由这张卡自己记着（v1.76）**：卡片底栏那颗模型下拉在媒体卡上选的就是它，存在卡片记录上（不是会话上），没选过就是「自动」——生成时按模型族去模型配置里挑。选了就按这个 id 反查路线，配置里没有这个模型时**如实报错**而不是换一个去画。这个选择随目录走（进板面文件），换台机器打开同一份作品仍然生效。**所有卡同一个尺寸：400×252，卡面正好 16:9（v1.77 → v1.79）**。图片与视频先放大（卡面就是产物本身，小卡上一张 16:9 的图只剩一条窄带；而高度若按两倍 280，16:9 的图上下各空一条底色，所以高度由面板 16:9 反推：398×224 + 卡头 26 + 边框 2 = 252），随后文本 / 设计 / 应用 / 音频也统一到这个尺寸——画布上不再有两种节拍。只改占位：卡头、名字与字号照旧，引用线、命中区、取景、缩略图、排版间距与控制带锚点都跟着这个尺寸走。**产物出来之后，图片卡与视频卡改按产物的真实宽高比坐（v1.80）**：16:9 只是默认值——方图、竖屏视频铺进 16:9 的卡面照样留底色。比例由浏览器量（`naturalWidth` / 视频的 `videoWidth`）、写进卡片记录、随板面文件走，宽恒 400、高按比例反推（1:1 ⇒ 400×426，9:16 ⇒ 400×736）；没量过、量不出来或值说不通就**不写**，回到 16:9。排版按各自的高排，竖卡不会把自己的下半身让给下一张。**产物也可以从本地直接导入（v1.81）**：选中媒体卡，胶囊上的〔导入〕选一个本地图片 / 视频 / 音频，它就成了这张卡的产物——按自己的名字落在画布文件夹里，卡片名与形态跟着它走，同一张卡再导同一个名字算替换。只收这三种，上限 16MB（与「一次读回多少字节」同一个数），被拒时说清是「不是媒体」「太大」还是「空文件」。**音频和图片、视频一样，是模型按描述生成的（v1.82）**：用户原话「参考视频，音频也是模型生成，模型参考 doubao-seed-audio-1-0」。所以音频卡的 `prompt` 是**导演指令**，不是朗读稿——一条里可以写多角色对白、音效、配乐与环境声（「雨夜便利店，两人压低声音争吵，背景有收银机滴滴声」），要念的台词直接写进去，音色与语气也用一句话说清（「慵懒御姐」），**不用选音色 id**；单次最长 120 秒，超了就分段做。产物格式跟着卡片自己的扩展名走（叫 `.mp3` 就一定拿 mp3，不会拿一段 wav 冒充）；生成是**同步**的（不像视频要轮询），出完立刻能在卡上播，也会立刻按产物的真实比例坐（v1.80 那条闭环）。 |

### 3.3 卡片-会话绑定

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F3.1 | 会话自动创建 | 创建卡片时自动创建独立 Agent 会话 |
| F3.2 | 会话元信息注入 | system prompt 注入卡片路径、形态、项目风格档案 |
| F3.3 | 会话隔离 | 卡片 A 的会话看不到卡片 B 的对话历史和文件内容 |
| F3.4 | 会话持久化 | 对话历史持久化，卡片重开时自动恢复 |
| F3.5 | 会话状态指示 | 卡片上**没有状态点**：运行中由流光说（F3.7），流光不在就是「没事发生」——卡面因此只有名字与产物预览两行信息，**产物确实丢了**的卡片以预览变淡示意。变淡**不是**「这个文件现在读不到」：还没写过产物的空座位（刚落座等着写、位图等着生成）与探针答不上来的卡都照常显示，因为那都不是「丢了」——判据由 Host 给，于是变淡、计数与清理（F1.11）用的是同一个集合。卡片那圈边框是**完整**的：四角都是圆角，包括左右下角——贴齐卡片内缘的两层各自那一侧给的是**同心**圆角，否则它们的不透明底色会在圆角处把边框盖掉一段（v1.34） |
| F3.6 | 卡片切换 | 卡片胶囊上的「对话」按钮把主区域切到该卡片会话（对话页面本身不再有画布卡片标签页，见[技术文档 §8](./DeepSeek-Harness-Canvas-技术文档.md)） |
| F3.7 | 生成中反馈 | 会话运行中时卡片亮起**流光**：一道斜切光带从左扫到右、匀速不停顿，画在独立子层上盖住整卡——卡片自身不能裁剪（引用端口悬在卡外）；名字与预览照常显示，光的往复就是「正在产出」的整句话。卡面只微亮一档、**边框不变色**（边框归悬停与选中）。回合结束流光即停，画布重读产物摘要、卡面回显新产物。**「减少动态效果」下不熄灭**：同一条光带照扫，只把动感降下来——光在动是这张卡唯一的进行中信号，停摆的光与「卡住」无从区分（v1.19 / v1.21） |
| F3.8 | 双击全屏预览 | 双击卡片全屏展示产物内容，**弹窗就是整块画布大小**（与画布区同宽同高、不留边距、不切角）；头部只有产物名、形态、关闭 ×，**文本节点另有一条「预览 / 编辑」单选组**（F3.12）。按形态取预览器——Markdown 渲染、图片 / 视频 / 音频、HTML 与 Deck 沙箱 iframe、CSV / JSON 表格、其余纯文本兜底；**加一种形态 = 加一个文件 + 注册表 import 一行**，弹窗与控制带一行都不用改。产物全文经通道传输，过大时截断或如实提示上限；**预览里的链接**（v1.36）——页内锚点原地跳、绝对地址真开新窗、相对地址拦下并显说明条（沙箱里的相对基准是宿主页面）（v1.6 / v1.23 / v1.24 / v1.42） |
| F3.9 | 提示词回填 | 控制带的输入框与 ⤢ 全屏弹窗**共用同一份草稿**（一盒两尺寸，见 F3.11）：两者在用户未编辑时都显示该卡片**最近一条自己发出的消息**（逐字保留换行），冷会话（本页从未打开过）照读；插件注入的引用上下文不算用户的话、不回填。用户键入的草稿优先于回填、按卡片各自保留（v1.9） |
| F3.10 | 操作胶囊收敛 | 选中卡片上方的动作胶囊只留**没有其它入口的动作**：对话、**导入**（媒体节点专有，v1.81）、**手动输入**（文本节点专有，见 F3.13）、导出、从画布移除。「打开」删除——产物展示归双击全屏预览（F3.8）；「建立引用」删除——引用已由卡片两侧端口与控制带 ⊕ 菜单覆盖，胶囊不再放第二扇更弱的门（v1.10） |
| F3.11 | 卡片控制带 | 选中卡片下方是一条**控制带**：提示词**输入框**（⌘/Ctrl+Enter 发送，空稿禁用发送；`@` 引用画成标签，F3.18）与引用 chips、⊕ 引入入口、**⤢ 放大输入框**、模型席位一行排开。**右下角有一颗把手，拖它就是把这条带子放大**（宽与输入框的高一起走）：放大的只是**空间**——字号、行高、内边距、圆角与那三行结构一律照旧（放大态用的是同一个输入框、同一套字，没有另一副更大的），多出来的地方**只归输入框**；**锚在卡片中心**——放大时左右两侧对称地长，输入区始终与节点居中对齐（代价是右下角那颗把手只吃得到半个位移，所以宽按两倍走，才跟得住光标）。往回拖缩得回去，按一下不移动则什么都不改；拖出来的大小**按卡记着**（本机内存，不落盘、刷新回默认）。**右上角那颗 ⤢ 打开的是同一个控制台换了个壳**：里面还是那三行（材料行 + 输入框 + 底栏），输入框的字号/行高/内边距/圆角与行内逐字相同、草稿也是同一份，只是容器更高、输入框占得更多。**两处按钮各管各的壳**：带子右上角那颗是 **⤢ 放大输入框**，弹窗**头部右上角**那颗是 **⤡ 缩小输入框**——它开合的是这个弹窗，所以站在壳的头上、不混进那三行里（材料行与行内逐项相同，一颗多余的按钮都不多）；Esc 与点遮罩同样可以退。卡片上没有「还没有消息。」一类的状态文字、**也没有状态点**——进度由流光（F3.7）说、产物由卡面预览说；发送入口是条内输入框、⤢ 弹窗与「对话」胶囊三条（v1.45）。底栏那颗**模型席位在还没有会话的卡片上照样能选**：卡片可以先于它的会话存在（建卡不等于开会话，技术文档 §十一 差异表第一条），所以席位在这种情况下替这张卡**先开一次会话再写选择**，而不是把自己禁掉——从前它是 `disabled={sessionId === ''}`，于是新建的图片 / 视频 / 音频卡片上那颗下拉框是一枚按不动的按钮（v1.71）。**下拉里列的是「能当对话模型」的那些，不是「配了哪些模型」**：视频 / 图片生成模型（seedance / seedream 一族）不出现——选它们不会让这张卡出得更好，只会让这段会话的下一次请求以 400 回来（v1.73）；已经选进去过的**不静默改**，但按钮与菜单都会说明白要换一个。**媒体卡上这颗下拉问的是另一件事（v1.76）**：它选的是**这张卡由哪个模型生成**（图片卡只列图片模型、视频卡只列视频模型、音频卡只列语音模型），写进卡片记录而不是会话，所以**不需要先有会话**——刚建的图片卡一落座就能选；没选过时显示「自动」（生成时按模型族去模型配置里挑）。这样分开之后，v1.73 那条 400 不会回来（对话卡里仍然没有生成模型），而图片卡重新有了图片模型可选——上一版把整族删掉，是把「别让生成模型当聊天模型」错读成了「媒体卡不该有模型可选」 |
| F3.12 | 文本就地编辑 | 文本节点（Markdown，以及按扩展名分不出形态的纯文本文件）在预览弹窗里可以**手动改**。切换是头部那条**单选组**（预览 / 编辑并排，选中的一半是实心拇指——当前在哪一面是看出来的，不是从按钮上的字反推的；方向键跟着选中态走、到头不绕回；**焦点进编辑器后方向键归光标**）。切到编辑面就是整块画布大小的等宽编辑区。写盘两条路：**打字停手即自动落盘**，以及 ⌘/Ctrl+S 或头部「保存」的**立刻落盘**（后者写完重读并刷新画布；两条路都交回预览面）。**预览面渲染的是缓冲区而不是磁盘**——改完字切过去看到的就是刚打的那一段，否则会让人以为白改了；**未保存时**头部挂「未保存」标记，此时关闭先问一句，草稿在两面之间来回切换时留在原地——**不静默丢字**。**读不全的产物不给编辑**：编辑器整篇写回，会把没读到的那部分一起覆盖。**写入被拒**时不说原生错误、也不无限重试：重试也不会好的**暂停自动保存**并把「重试」交给用户，一时性的按退避重试；错误条主句说人话、原生错误降为细节行（v1.26–v1.29） |
| F3.13 | 手动输入 | 胶囊在「对话」之后多一枚**手动输入**，只在文本节点上出现（判定与 F3.12 同一份；文件夹、图片、Deck、应用一律不给——编辑器整篇写回，给它们一枚编辑钮就是把文件改成文本）。点它打开**同一个**预览弹窗（F3.8），只是**直接落在编辑面**：手动写这一篇与让模型写这一篇，是同一张产物的两条路（v1.26）。**产物还没有落盘时**（座位可以先于它的产物存在，F1.11）点它不给你一句「产物不存在」：先替这张卡落一份**空**文件，再开编辑面等第一行字——这条路本来就是从无到有地写第一段，而按钮也不该恰好在「还没有东西可写」的时候隐身（摘要读不到时回落问卡片自己记着的形态）。三条界线：空文件是**在**的（那是用户自己清空的结果，不是我们要补的缺）；**双击看预览**不会替你写文件（看是看、写是写）；落盘失败照实说（写不进去时说写不进去，退回「产物不存在」会让人以为是自己点错了）（v1.57） |
| F3.14 | 预览里的元素选择 | HTML 家族的**全屏预览**头部多一枚**元素选择**开关。**按下即进入选择模式**：**这一页暂时变成只读的**——照浏览器调试工具的元素选择那套，鼠标移到哪儿就圈住哪儿，页面自己的悬停、按钮、输入与文字选择一概收不到这一下；鼠标在整页范围内统一是十字。指针底下的元素**当场亮框**并写出它的记号。**单击即选中**，这一击**不落到页面自己的按钮或链接上**，随即在元素正下方弹出**提示词框**：产物文件、节点记号、选择器路径与**这个节点自己的源码**那几十行定位原文已嵌在框里，但**折成开头的一枚元素标签**（`◫ 节点名`，引用标签的第四种长相，画法归 F3.18）——点的节点一眼可见，定位原文仍是值的一部分、发出去的提示词与逐字写出这段一模一样，整枚标签可原子删掉（等于这一笔没选过）；原文对不上时（草稿被人动过）整段退回普通文本编辑，展示让路、值不动。光标落在末尾且那一行**滚进可视区**，等用户接着写。**给的是定位不是补丁**——序列化结果与文件原文未必逐字相同，模型照路径自己去文件里落刀。写完后发送走与画布输入框**同一条**通道，交给这张卡自己的会话去改文件。说明条**一律浮在帧上、不占排版位**——「正在选元素」那条随模式在单击那一刻消失，发送之后的回话也一样浮着；它们若排在流里，出现或消失的那一瞬就会把整帧顶走一整条（实测 43px），而圈与框的位置是拿帧的坐标画的。**选元素的时候页面还能滚**（不然下半页的元素够不着），**但一笔选定、框开着之后，页面连动都不动**：滚轮与滚动位置一起冻住——用户正在写"改这一段"，页面在底下滑走，圈住的位置就不再是他在说的那一段了。**发送之后框不收**：圈上亮起与卡片**同一道流光**（光在动 = 正在产出），框留在元素旁等产物真的变，产物一更新才自己收起（用户在这期间又写了下一句则留着，不替他丢那句话）。**圈与框一直钉在这个元素上**：帧的位置是**活的量**——手里攥着一笔时持续重测（界面一变量一遍、帧自己的大小变了量一遍、窗口缩放量一遍），帧被谁挪走，圈与框都跟着它走，绝不从元素上错开。**关掉预览再打开，这一笔摆回原样**（圈、框与草稿都在）——它按卡记着、比弹窗活得久；**改动已经落地、或用户明确关掉（× / Esc），就不再摆回来**。手里攥着一笔时工具按钮按不动：重新选会把这正在改的一笔顶掉。页面里自己的滚动条在选元素时滚不动（整块预览被一层透明层盖住）——选不到的元素先退出模式滚过去，再进来选（v1.39 / v1.44 / v1.56） |
| F3.17 | 改动落到本卡产物 | **同一个卡片的多轮对话只产出这一份产物**：凡涉及改动的回合一律**覆盖本卡产物**，不新建卡片、不留 `-v2` / `-copy` 这类第二份让人挑；「再改一下 / 换成… / 加上…」是**修订**，不是新产物——对话本该收敛到一份越改越好的东西，一轮一个新文件等于把用户手里的线索打散，画布上还多出一张他本来只是想改一改的卡。**产物是站点 / 应用的入口文件时**，同目录的那一族文件就属于**同一份产物**（F5.4），照常编辑；越界的只有「另起一份交付物」。**建卡是用户的动作**：卡片由用户拖出节点或明确要求产生，会话不会因为「想写点什么」而顺手建一张（`canvas_create_on_board` 同理，不拿它回答一次改动）；只有用户明确要一份**独立**的交付物时，模型才把这句话说出来、由用户去建——既不悄悄分叉，也不拿别的东西盖掉本卡产物。规则写进卡片会话的系统提示词（F3.2），**没有机械强制**：插件不禁止写别的文件（站点、应用本来就多文件），管住的是「另起交付物」这一件事（v1.46） |
| F3.18 | 提示词里的引用标签 | 输入框里的 `@文件` 记号**画成一枚标签**——图标（或缩略图）+ 文件名 + 可选徽标，整体是一枚**不可分隔的原子**：Backspace / Delete 在标签边界上删的是**这一枚引用**（不是它的一个字符），标签内部没有光标可落，复制 / 剪切在剪贴板里还原成 `@路径`，粘贴只取纯文本（富文本带进来的那棵 DOM 正是「内容就是值」这条边界最容易被撕开的地方）。**标签只是画上去的**：它序列化出去的是**它自己那串字符**（`@a.ts` / `@"my brief.md"` / `@hero.png <point>420 380</point>`），不是从路径重新拼的一份——宿主记号有三种形态，反推就可能把发出去的提示词改掉一个字节；「拼回去逐字节等于原文」由单测与真浏览器判据共同钉住。**类型按扩展名定**（判据只有一份、写在路径里，卡片离开画布也读得到）：`code` / `image` / `video` / `audio` 指一份**文件**，`mark` / `region` 指一张图上的**一个点或一个框**（坐标归一化到 0–999，与图像模型同一套刻度；紧跟在文件记号后面的 `<point>` / `<bbox>` 并进**同一枚**标签——「这张图上的这个点」是一件事，不是两件；坐标还没有界面产生，契约先钉在解析器里，等图像预览器有了圈选）。**标签写文件名，不写序号**：本插件的锚点就是路径，模型照它自己去读那一份文件，视觉内容不走第二条通道——两枚同名图片因此在提示词里也分得清谁是谁。**`@` 候选菜单**：光标前打 `@` 就浮出候选——这张卡已有的引用来源在前（关系是板上画着的）、画布其余卡片在后，各截 8 枚，键盘上下 / 回车选中、Esc 收起；媒体类候选与标签都画缩略图（分批读产物，取不到退回类型图标——缩略图是锦上添花，不是引用的前提），**缩略图回来不端走光标**：草稿没变、只是事实变富时，重画前后先量后画，光标与选区原样还回去。两处落点（控制带与元素选择的提示词框）是同一个组件；**行高是判据**——一枚标签（含缩略图）不许把正文那一行撑开，否则插进一句话中间就把整段的行距改了（v1.48） |

### 3.4 引用关系

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F4.1 | 引用关系 | 卡片之间唯一的连线类型：B 引用 A。有向、可多重（一张卡片可有多个上游，也可被多张卡片引用） |
| F4.2 | 引用建立 | **从锚点拖线**：按住卡片侧边的端口拖出去，拖拽中的线从**锚点（端口圆心）**起笔、终点跟随指针，样式为**细线、无箭头**——它还不是一条关系，只是一个还没落地的动作。松手落在另一张卡片的端口上即直接建立（只需定方向，不需要选类型）；落在空白处则就地弹出「新增节点」弹窗（F4.8） |
| F4.3 | 引用持久化 | 引用数据作为画布元数据独立存储、不随卡片走。存储键由两端卡片 id 转义拼成——卡片 id 是路径、带点带杠，而存储介质对键有更严的字符集要求，不安全的键会在写盘时被整体拒绝。**v1.47 起同时写进目录里的板面快照**（F1.10）：本机真源仍是存储领域，那份快照负责让引用关系跟着目录走，所以换台机器打开同一个目录时边还在（从文件导入的边要过与手绘连线**同一道**校验，自己成环、重复、端点不在板上的边一律丢掉） |
| F4.4 | 引用可视化 | 落定的引用线与**拖拽中的线同款**：细线、实线、无箭头、breeze 色（F4.2）——线上没有第二个样子，选中卡片时只把不透明度提亮一档。**线不可交互**：整层不接指针事件，线只负责看，永不拦截跨越它的拖拽（解除引用走 chip 上的删除钮，F4.9；不在画布上点线）（v1.18） |
| F4.5 | 自动对账 | 产物中真实引用的素材自动生成引用边（HTML 里的 `src`、Markdown 里的图片链接等） |
| F4.6 | 上游链排布 | 按引用链分层：上游在左、下游在右，同层对齐。三种策略——**按深度成列**、**纯网格**、**整理**（链上的卡按链排、散卡在下方网格收拢），Agent 工具可指定。**画布左下角的「自动排版」按钮**走同一条通道、用整理策略（v1.22） |
| F4.7 | 上游追溯 | 查看当前卡片的完整上游链（含间接上游），以及引用它的下游卡片 |
| F4.8 | 空白落笔建卡 | 拖线放到**空白处**不再直接作废：放手点就地弹出「新增节点」弹窗（应用 / 文本 / 图片 / 矢量图片，与 dock 新增同一份菜单），点一种形态即**当场建卡并连线**——新卡片按放手点落位，让它的端口正好接住刚才的线头，于是细线不是「跳」到卡片上、而是就地变成引用边；弹层向屏上空间更大的那一侧张开。**点弹层以外、按 Esc、或手松在画布之外，都取消这一笔**——不留卡片也不留线 |
| F4.9 | 引用解除 | 控制带里每枚引用 chip 的**右上角挂一枚删除钮**：一条 chip 就是一条**直接**引用边，点删除即删掉这条关系，画布与存储同步退场。chips 只列直接边——**间接**上游是更上面某张卡的关系、删无可删，不进 chips（这也与引用通道一致：材料本就只取上一级，F5.8）；chip 加大一号，卡片不裁剪，角标探出上缘（v1.20） |

### 3.5 引用作为输入通道

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F5.1 | 拉模式注入 | Agent 或用户主动调用工具获取上游材料，分**产物摘要**与**上游产物文件引用**两条路（v1.37） |
| F5.2 | 摘要注入 | 注入内容为文件路径 + 内容摘要 + 关键结构，非全文。与文件引用**并列而非回落**：文件引用说材料在哪、模型按需去读；摘要把材料立刻摆到眼前，页面级摘要仍由它承担（v1.37） |
| F5.3 | 显式引用 | **v1.37 落地**：卡片 ⊕ 菜单「引用上游产物文件」——用户显式把上游产物**以路径**提交给本卡会话，写法就是 Harness 自己的 `@file`（与宿主实现逐字节一致）。**不复制内容**：注入的只是一组名字加一句「这是引用不是内容」，读不读、读哪一段由模型自己决定 |
| F5.4 | 引用可达性 | **v1.37 落地**：名字必须**真的解析得到**——引用写的是卡片的产物文件路径（记录在卡片的 `file` 字段上，v1.49），产物落在画布根下的同一个位置，模型读一下就拿到材料。**卡片是文件不是目录**（站点 / 应用这类目录形态的卡片坐落其入口文件）：报名字时一律按文件形态给，不推目录 |
| F5.5 | 引用如实 | **v1.37 落地**：工具如实回报每一项的名字、路径、形态、存在性与大小（没写盘就标为不存在，不编大小），并把**语法写不出来的路径**（含引号或控制字符）**上报而非悄悄丢掉**；注入消息随「插件来源」标记持久落盘，事后可查 |
| F5.6 | 变更通知 | 上游产物被改后，向**存活**的下游会话注入一条变更通知；已关闭的卡片没有会变陈旧的上下文，空闲会话**不被后台写入唤醒** |
| F5.7 | 响应策略 | 配置项三档：**不通知** / 只报「上游变了」/ 连新摘要一起带上（省掉一次工具调用）。**注意分工（v1.37）**：变更通知这一路走**产物摘要**——它要的是「立刻把材料摆到眼前」；文件引用不需要通知，因为路径指向的**正是那个文件**，上游怎么改它都指得对，重新取用只需再报一次名字 |
| F5.8 | 引用只取上一级 | **v1.46**：一张卡片能取用的材料**只有它的直接上游**（上一级），不做穿透引用——这是三条通道共用的一条规矩：每轮提示里的引用块、`canvas_read_sources` 的摘要、`canvas_reference_files` 的名字，一律只报本卡自己那几条边指向的产物。理由：链要**折**不要**摊**——产物本应把上游材料消化进自己那一份，把祖父的产物塞进孙子的提示词，花的是上下文、拆的是画布自己画出来的那条流水线；而「本产物建立在它之上」这句话，隔一层就不成立了。**能看的仍然看得到**：F4.7 的引用链照旧报全链（含间接），`canvas_get_sources` 拿链、`canvas_read_card` 读其中任一份，属实**明确去取**，不是默认送到。配置项 `sourceDepth` 自此只作用于链视图，不作用于引用 |

**两条通道，一条边**（v1.37）：同一条引用边有两种可取用的材料，**各司其职、互不替代**。**为什么底层是文件而不是会话**：边指向的那份产物**可能是手动新建的**——没有任何会话生成过它；也可能是**某次会话产物被二次编辑后的版本**——内容已经不等于那次会话的记录。拿会话去代理产物，这两种情况下都会**指错**（把「谁生成过」当成了「这份东西是什么」）；文件引用不问来历，只认磁盘上那一份。**文件引用是指针**——它把上游产物的路径交给新会话，内容一个字都不复制，因此**不会失效**、**不占预算**、**不被截断**、**没有缓存与失效时机要定义**；代价是模型要自己读（多一次工具调用），以及**可能不读**——所以引用块里写明「这是引用不是内容，没读过的文件不要描述」。**产物摘要是快照**——把材料的一份有界摘要**立刻**摆进上下文，零调用，但有损、有预算、每次现算。选哪条按「下游现在要的是什么」定：**知道有哪些材料、按需取用 ⇒ 文件引用**（这是默认）；**立刻需要那份材料在场 ⇒ 摘要**。**唯一不许含混的是「什么都没给」**：没有上游是事实，路径写不出来则**明说写不出来**——一条正文为空的注入消息会消失，模型会以为这张卡根本没有上游，那比「说了、但一个也没命名成功」更糟。

### 3.6 Agent 跨卡片工具集

工具名一律用 `canvas_` 前缀 + 下划线分隔（如 `canvas_read_card`）：名字会作为工具名发给模型供应商，字符集被限死，带 `.` 的名字会被直接拒绝。（[技术文档 §12](./DeepSeek-Harness-Canvas-技术文档.md) 的第 1 项开放项由此关闭。）

| 工具名 | 功能 | 参数 |
|--------|------|------|
| `canvas_read_card` | 读取指定卡片产物摘要 | `cardId` |
| `canvas_read_sources` | 读取引用来源（直接上游产物）的产物摘要；只取上一级，F5.8 | 无 |
| `canvas_reference_files` | 把引用来源（直接上游产物）以**文件引用**提交给本卡会话：不复制内容，模型自己按需去读；只报上一级，F5.8（v1.37） | 无 |
| `canvas_link_source` | 声明本卡片引用另一张卡片 | `sourceCardId` |
| `canvas_get_sources` | 获取当前卡片的引用链（直接上游、间接上游、下游） | 无 |
| `canvas_inject_card` | 将指定卡片产物注入当前会话 | `cardId, mode` |
| `canvas_read_board` | 读取画布当前座次与引用边 | 无 |
| `canvas_arrange_on_board` | 按引用链语义化摆位 | `strategy` |
| `canvas_create_on_board` | 创建便签或卡片 | `type, content` |
| `canvas_organize_board` | 归纳收纳 | 无 |
| `canvas_link_source_on_board` | 画引用线 | `from, to` |
| `canvas_generate_image` | 生图 | `prompt, cardId` |
| `canvas_export` | 导出产物 | `cardId, format` |
| `canvas_publish` | 发布产物 | `cardId` |

**两类工具，两套「我是谁」**（v1.31 修订）：前六项以**卡片**为作用域——调用方身份从会话解析，解析不出就直说「请先打开这张卡片的对话」，不猜、也不退让；其余八项以**画布**为作用域，取项目分两级：**用户当前打开的画布**优先，全局为空时**卡片会话回落到这张卡片所属的画布**——卡片会话是唯一「项目确定」的地方，对它回「没有画布」等于对一个明明在画布里的会话说没有画布；两级都取不到才拒绝。所以同一个「读取画布座次」，在画布上的卡片对话里能跑，在无关的普通会话里会被拒——这是设计，不是故障。

### 3.10 导出与发布

| 编号 | 功能点 | 说明 |
|------|--------|------|
| F10.1 | 多格式导出 | HTML / PDF / PPTX / PNG / SVG / zip。三档形态点导出给的东西不一样，因为「这份产物该怎么交出去」本来就不是一件事：**文本节点**是一张四行菜单——Markdown / 纯文本 / Word / PDF，四种格式各有各的去处，没有哪一个能当默认；**应用节点**是一击：整份产物打成一个压缩包落进本机，解压出来是**一层同名文件夹**（不散在解压目录里）——「整份」就是整份，应用卡记的地址是入口页 `index.html`，而导出的边界是它所在的**整个文件夹**，样式、脚本、素材全都在包里（v1.58 修过一次：此前按「记的那个文件」打包，于是导出的是**一个只有 index.html 的包**——解得开、打得开、一打开没有样式也没有交互）；**设计节点**也是一张四行菜单——**Figma 文件 / 图片 / PDF / PPT**（v1.59），四样都在浏览器里就地画出来：`.fig` 是**整份文档一个文件**（拿进 Figma 打得开，文件列表上还有一张真的缩略图），**图片**一容器一张、**2 倍像素**（多个容器就打成一层同名文件夹的 zip），**PDF** 也是**整份文档一个文件**（一容器一页，每页尺寸跟着那个容器，不统一成 A4）；交出去之前**先在 SVG 上修三处**（v1.64，起因是真机报的「导出 PDF，文本换行，和圆角矩形渲染不正确」）：**文本按节点宽度折行**（上游那张 SVG 里整段只有一个 `<text>`、不折行，会一路冲出容器右边界——而画布是按宽度折的，所以「画布三行、PDF 一行」）、**裁剪矩形补上圆角**（`clipsContent` 的容器此前套的是一层**直角**裁剪，圆角容器里铺满的子块会把四个圆角填平，画布上露白底、PDF 里变直角）、**超半轴圆角夹成画布那个值**（画布是整体按比例缩，SVG 的 `rx`/`ry` 是各自夹到半轴——200×140 给半径 100，一个画成超椭圆、一个画成正椭圆）。三处都只改**交给 svg2pdf 的那份 SVG**，不动场景图，也不动另外三条出路。**`.fig` 那条也在交出去之前改写一遍**（v1.65，起因是真机两轮报的「导出 Figma 文件，文字不会换行 / 文字错位 / 部分文字不渲染 / 渲染成一个方块」与「文字在圆角矩中本来是居中的，在 Figma 中变成了居左」）：四句话同一个根——fig 写器把**整段文字**一次性丢进字形烘焙，然后**把所有字形按同一行、从节点原点起**摆（`baselines` 只写一条、`y` 恒为一个行高、`\n` 还会落到 `.notdef` 变成方块）。于是**多行**全叠在第一行上，而**居中 / 右对齐 / 垂直居中**这几件事在产物里只剩一个字段还写着（坐标却是按左上对齐烘的）。**这条与 PDF 那条不同**：PDF 还有一层中间产物（SVG）可以修，`.fig` 是终产物，只能**改输入**——把节点改成写器烘得对的那种形状：**一行一个节点、框贴住内容、左对齐**，位置取**画布自己那份段落**的逐行量（折行位置与对齐偏移因此必然与画布一致）；另一件是**把中文字面按稿子用到的每个样式名登记一遍**（写器按「字族 + 样式名」取字形与摘要，而手里只有一支 Regular——写着 700 的字取到 `null`，在 Figma 里整段不见）。只碰**不修就会烘歪**的节点，单行且贴着左上的原样不动。**已知项**：两端对齐（`JUSTIFIED`）的多行文字在 `.fig` 里会按左对齐烘——段间那点拉伸是排版器算出来的，烘不进去（技术文档 §十二）。**PPT** 一页器一份幻灯片序列（多页就是多个 `.pptx` 装一个包）；**这条本来是「可编辑混合导出」**——文本 / 矩形 / 椭圆 / 直线转成原生 PowerPoint 元素，拿去还能接着改——但它在**每一页**上都可能整页退成一张图片（v1.66，起因是真机报的「导出 PPT，每页都要能再次编辑，而不是为一张图片」）：闸是上游的（root 容器开着裁切、又有子孙越界 >0.5px 就放弃逐元素转换），而**我们的容器默认就开裁切**、AI 画稿时装饰子块贴边又是常态。交出去之前把越界**预夹进它所有裁切祖先边界的交**（`core/artifact/design/pptx-preclip.ts`）——越界那部分在画布上本来就被裁掉不可见，夹掉它逐像素不变；只有**直角矩形叶子**是数学上可证明的等价，**夹不动的那些（圆角矩 / 椭圆 / 文本 / 矢量）另有一步**（v1.68）：套一个同尺寸的裁切框、连裁切一起画成一张 PNG，再用它顶掉（`core/artifact/design/pptx-raster.ts`）——图片是矩形，收进框之后「裁剪」与画布上「裁掉」是同一件事，而**上游那条闸是整页生效的，一个夹不动的越界子孙就够让这一页的可编辑性全丢、所有文字跟着落进那张图**。转过 / 翻转的越界子块不碰（坐标换算不成立），遮罩不碰（靠「和兄弟的关系」生效），画不出来就回滚成原样。交出去的那三样里，**字体名必须换掉**（v1.60–v1.61）——那三份产物会被别人的软件解析：PPT 的字体名交给对方的 PowerPoint 排、`.fig` 的交给 Figma 取字形轮廓、PDF 的交给文档自己的字库。留着设计稿内部那个名字（`Inter`，而它没有汉字字形），中文会分别**整段丢**、**全画成同一个形状**、**变成乱码**。这三条都在浏览器里就地完成，**不依赖部署后端**——没有 `dsh-canvas.capabilities` 的部署上，它们照常能导。三档共同的规矩是**画不出来 / 装不下就如实说不导**，不给半份。导出之后画布左上角那一条**按收场换色**（成了 / 这次没导成 / 出错，三档一眼分得开，不必读完一行字才知道），并且**每一条自己带一枚 ×**——一句话说完了就不该赖在画布上（v1.58）。**三种媒体卡（图片 / 视频 / 音频）也各有自己的一击**（v1.83）：点一下，磁盘上那份产物**原样**落进下载目录——不转换格式（卡片里本来就是一个现成的 jpg / mp4 / mp3），文件名跟卡片走（改过名就跟着改）、扩展名与内容跟产物走；拿不到整份（还没生成、或大到超过一次能取回的上限）就照实说不导，并指出它在画布目录里。这条通道**不依赖部署能力**，没有 `dsh-canvas.capabilities` 的部署上照常能导 |
| F10.2 | 即时导出 | 可编辑 PPTX 导出应在一秒级完成 |
| F10.3 | 一键发布 | 发布到子域名，下线即回收 |

## 五、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 引用注入模式 | 拉模式优先 | 会话隔离干净，上下文可控，避免膨胀 |
| 会话可见范围 | 仅当前卡片 + 显式引用 | 防止上下文污染，聚焦单一产物 |
| 连线范畴 | 只保留「引用」一种 | 语义被收窄后，画布结构不会随协作话术膨胀；其余语义交给命名、产物内引用与便利贴 |
| 形态认定 | 文件证据自动认定 | 通用性自然获得，加形态不改分支 |
| 卡片 id | 文件路径 | 与文件系统一一对应，无需额外映射 |
| 引用存储 | 画布元数据独立于产物文件 | 文件系统不擅长表达跨文件依赖 |
| 引用方式 | 快照式 | 可追溯，避免实时同步的复杂性 |
| 双端形态 | 双端插件（Host Cordis + Client Web） | 画布是重交互 UI，必须跑在浏览器半；Host 半持有文件、会话与工具 |
| 双端通信 | 一份 wire 契约，三处引用 | Host manifest 与 Client 贡献指向同一 descriptor 数组，结构上不可能漂移 |
| 数据落点 | 存储领域（domain）而非自建文件 | 复用后端路由、版本校验、写链与 `domain/changed` 通知 |
| 画布跟着目录走（v1.47） | 存储领域**加**一份随目录走的板面投影（F1.9/F1.10） | 只存存储域时「画布＝这个文件夹」只在同一台机器上成立：改名即换一张、换机器即空板。反过来只存文件，就要自建原子写、并发串行与版本迁移，把存储域白给的 schema 校验与写链再写一遍。**分工是「谁是真源」与「属性归谁」**：本机读写仍走存储域（投影可以慢一拍、可以失败），作品的关系与布局跟目录走、本机态（会话绑定、视图）留下 |
| 会话隔离手段 | 工具注册作用域 + 可见性过滤 | 把隔离做成结构约束，而不是提示词约定 |
| 文件访问 | 统一走 `ctx.fs` seam | 自带版本守卫、沙箱策略与写前 waterfall，直接可用 |
| 画布承载席位 | 右栏停靠面为主、全屏覆盖层为辅 | Web Client 主区域属于对话，不自造席位 |
| 产物预览 | 复用右栏 tab 类型注册表 | 按资源地址认领，`extension` 档压过内置查看器，卸载即恢复 |
| 卡片会话的模型 | 自建 agent 时补 `agentOptions`，会话选择经 `sessionController.selectModel` 装回 | 卡片会话不走控制器的组装路径，缺前者装配即失败、缺后者跨重载丢选择；而选择策略本身仍归控制器 |
| 模型选择器写在哪 | 会话级（宿主投影）为真源，节点类型记忆只作"新会话继承" | 会话一旦自己选过就以会话为准，跨节点类型的记忆不覆盖已用过的卡片 |
| 卡片会话的工具 | 从部署的 agent preset 组装（`ctx.agentPresets.mount` 于工厂 `setup`） | Web 面已把面向模型的文件工具行从宿主组装移出、改由 preset 提供；自建会话不加入就一个写盘工具都没有，而产物只能靠普通文件工具写出来 |

## 六、产品边界

### 做什么

- 通用文件产物的创作与管理
- 卡片级会话隔离与引用驱动协作
- 任意形态的产物生成（PPT、网页、文档、图表等）

### 不做什么

- 不做实时多人协作编辑
- 不做文件版本控制系统（依赖底层文件系统）
- 不做独立的模型服务（复用 Harness 模型适配层）
- 不做重型渲染引擎（预览依赖浏览器能力）
- 不做通用关系图谱／语义网络（连线只有引用一种，其余协作语义不由结构承载）
